# معماری ایجنت پایش و پژوهش هوش مصنوعی (AI Sentinel)

> **وضعیت:** نسخه ۰٫۴ (رصد ژئوپلیتیک چین-آمریکا + پژوهش آنلاین/چندرسانه‌ای اضافه شد) — منتظر تأیید
> **ماموریت رصد:** مثل عقاب 🦅 — از بالا، همه‌چیز مرتبط با AI از هر گوشه دنیا (تقابل چین-آمریکا، مدیران، دولت‌مردان، نشریات معتبر، مقالات دانشگاهی)
> **ماموریت پژوهش:** دستیار متصل به اینترنت با ساختار Perplexity + آپلود فایل/عکس/صوت
> **الهام‌گیری:** worldmonitor + deep-research + aria + Perplexity
> **تصمیم‌های تأییدشده کاربر:** بک‌اند Python/FastAPI • UI فارسی (RTL) • LLM: هم API ابری هم Ollama (با LiteLLM) • هشدار فقط داشبورد (فاز ۱)

### ۲.۲ پایپ‌لاین پردازش رصد

```
   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
   │ Fetch    │──►│ AI Gate  │──►│ Dedup &  │──►│ Classify │──►│ Score &  │──►│ Deliver  │
   │ (کالکتور)│   │ (فیلتر   │   │ Normalize│   │ (دسته‌بندی│   │ Rank     │   │ (بولتن/  │
   │          │   │  مرتبط  │   │ (حذف تکرار│   │  موضوعی) │   │ (امتیاز  │   │  هشدار)  │
   │          │   │  با AI؟) │   │  و نرمال) │   │          │   │  اهمیت)  │   │          │
   └──────────┘   └──────────┘   └──────────┘   └──────────┘   └──────────┘   └──────────┘
        │              │
        │              └── آیتم غیرمرتبط ← ذخیره به‌عنوان «ردشده» (برای آمار/بازبینی)
        ▼
   ذخیره در پایگاه داده + ساخت embedding برای RAG
```

**نکته AI Gate:** منابع گروه B و C محتوای غیر-AI هم دارند (مثلاً خبر اقتصادی عمومی Economist). یک گام ارزانِ فیلتر (اول کلیدواژه، بعد در موارد مبهم LLM سبک) فقط آیتم‌های مرتبط با AI را عبور می‌دهد تا هزینه و نویز پایین بماند.

**دسته‌بندی موضوعی (Taxonomy)** — بر اساس دامنه تو:

| دسته | زیرمجموعه‌ها |
|---|---|
| 🏗️ زیرساخت (Infrastructure) | تراشه/سخت‌افزار (GPU, TPU)، دیتاسنتر، شبکه، inference-optimized infra |
| 🧠 مدل‌ها (Models) | معماری، پیش‌آموزش، fine-tuning، RLHF/DPO، مدل‌های چندوجهی، مدل‌های کوچک/on-device |
| ⚙️ الگوریتم‌ها (Algorithms) | attention variants، روش‌های بهینه‌سازی، sampling، quantization، distillation |
| 🔧 ابزارها و چارچوب‌ها (Tools) | فریم‌ورک‌ها (pytorch, jax, vllm, langchain)، Agent frameworks، evals |
| 📊 بنچمارک و ارزیابی (Evals) | MMLU, SWE-bench، لیدربرد‌ها، مقایسه مدل‌ها |
| 🧪 کاربردها (Applications) | صنایع، پزشکی، حقوقی، علمی |
| 🏛️ سیاست‌گذاری و اقتصاد AI (Policy & Economy) | مقررات دولتی، اظهارات مدیران و دولت‌مردان، سرمایه‌گذاری، M&A، بازار |
| 💬 جامعه و گفت‌وگو (Discourse) | بحث‌های اجتماعی، اظهارات افراد تأثیرگذار، جنجال‌ها |

**امتیازدهی اهمیت (Scoring)** — ترکیب خطی:
- `novelty` (تازگی؛ شباهت برداری با آیتم‌های قبلی — هرچه کمتر، تازه‌تر)
- `source_weight` (وزن منبع؛ اطلاعیه رسمی [OI] > ردیت)
- `relevance_to_profile` (تطابق با علاقه‌مندی‌های کاربر؛ cosine similarity با پروفایل)
- `momentum` (سرعت رشد بحث/ستاره/fork در بازه زمانی)
- `actor_weight` (وزن بازیگر؛ اظهار مدیرعامل [OI]/Nvidia/هوآوی > کاربر ناشناس)

### ۲.۳ خروجی‌های ماژول رصد

1. **داشبورد زنده** — جریان آیتم‌ها با فیلتر دسته/منبع/امتیاز/کشور
2. **بولتن روزانه/هفتگی** — خلاصه LLM از ۱۰-۲۰ آیتم برتر، دسته‌بندی‌شده
3. **هشدار در داشبورد** — برای آیتم‌های بالای آستانه امتیاز (فاز ۱ فقط داشبورد؛ ایمیل/تلگرام فاز بعد)
4. **نمای ترند (Tech Radar view)** — رادار/heatmap: کدام موضوع در حال داغ شدن است (حجم + رشد)
5. **🦅 نمای تقابل چین-آمریکا (Rivalry Dashboard)** — صفحه ویژه:
   - **ستون دوگانه:** اخبار اکوسیستم آمریکا در یک طرف / اکوسیستم چین در طرف دیگر
   - **تایم‌لاین رویدادها:** چه اتفاقی افتاد و طرف مقابل چه واکنشی نشان داد (مثلاً تحریم چیپ → واکنش هوآوی)
   - **شاخص‌های مقایسه‌ای:** تعداد مقالات، مدل‌های منتشرشده، سرمایه‌گذاری، شاخص‌های Epoch/Stanford بین دو کشور
   - **برچسب خودکار:** هر آیتم رصدشده دارای برچسب `camp: US | CN | EU | other` (تشخیص LLM) تا فیلتر فوری ممکن باشد

## ۳. ماژول ۲ — دستیار پژوهشی (Research Assistant)

### ۳.۱ قابلیت‌ها

| قابلیت | توضیح |
|---|---|
| **پرسش-وپاسخ RAG** | سؤال بپرس → پاسخ مبتنی بر حافظه رصد (مقالات/اخبار/اظهارات جمع‌شده) با ارجاع به منبع |
| **پرسش-وپاسخ آنلاین (Perplexity-style)** | سؤال → جستجوی زنده اینترنت + حافظه داخلی → پاسخ با **ارجاع شماره‌گذاری‌شده داخل متن** (مثل Perplexity: [۱]، [۲]...) + نمایش منابع با snippet |
| **Deep Research** | سؤال پژوهشی → ایجنت تکراری: جستجو ← خواندن ← اصلاح جهت ← گزارش نهایی (الگوی deep-research) |
| **آپلود فایل و عکس** | PDF / Word / Markdown / عکس → استخراج متن (OCR برای عکس) → ذخیره در حافظه پژوهش → قابل استفاده در RAG |
| **آپلود صوت** | فایل صوتی / گفتار → رونویسی (Whisper محلی یا API) → متن قابل جستجو و خلاصه‌سازی |
| **گزارش ساختاریافته** | تولید گزارش Markdown/PDF با ارجاعات، مقایسه مدل‌ها، جدول‌ها |
| **کتابخانه شخصی** | ذخیره مقالات، هایلایت، یادداشت، برچسب‌گذاری |
| **پایش موضوع** | «فلان موضوع/شخص/شرکت را دنبال کن و هر تحول مهم را گزارش بده» |
| **خلاصه‌سازی مقاله** | PDF/لینک بده → خلاصه + نکات کلیدی + ارتباط با کار تو |

### ۳.۲ حلقه Deep Research (مرجع: dzhng/deep-research + ساختار Perplexity)

```
سؤال پژوهشی
    │
    ▼
[۱] تولید پرسش‌های جستجوی اولیه (LLM)
    │
    ▼
[۲] جستجوی هم‌زمان در: حافظه داخلی (RAG) + وب (زنده/آنلاین)
    │
    ▼
[۳] ارزیابی و انتخاب نتایج (relevance filtering)
    │
    ▼
[۴] استخراج و خلاصه‌سازی یافته‌ها (LLM) — با ارجاع شماره‌گذاری‌شده [۱][۲][۳]
    │
    ▼
[۵] تحلیل شکاف: «چه چیزهایی هنوز نامشخص است؟» (LLM)
    │
    ▼
[۶] آیا عمق/پاسخ کافی است؟ ──نه──► تولید پرسش‌های جدید → برگشت به [۲]
    │ بله
    ▼
[۷] سنتز نهایی: گزارش ساختاریافته با ارجاع به همه منابع
    + نمایش منابع به سبک Perplexity (لیست منابع + snippet هر کدام)
```

- **عمق تکرار** (breadth/depth) قابل تنظیم توسط کاربر.
- **هر تکرار در داشبورد قابل مشاهده است** (ایجنتِ شفاف، نه جعبه سیاه).
- **موتور جستجوی وب:** SearXNG (self-hosted، رایگان) یا API خارجی (Tavily/Brave) — قابل تعویض از تنظیمات.

### ۳.۳ خط لوله فایل‌های چندرسانه‌ای (آپلود کاربر)

```
آپلود (PDF / Word / عکس / صوت)
    │
    ├── PDF/Word/Markdown ──► استخراج متن (pypdf / python-docx)
    ├── عکس ──► OCR (Tesseract یا مدل محلی) + درک تصویر با VLM در صورت نیاز
    └── صوت ──► رونویسی (Whisper محلی یا API)
    │
    ▼
ذخیره در پایگاه داده + ساخت embedding
    │
    ▼
قابل استفاده در: RAG • Deep Research • خلاصه‌سازی • کتابخانه
```

## ۴. هسته مشترک (Core Services)

### ۴.۱ اجزا

| جزء | انتخاب فنی | دلیل |
|---|---|---|
| **API بک‌اند** | FastAPI (Python) + Pydantic | انتخاب کاربر؛ اکوسیستم AI پایتون |
| **پایگاه داده اصلی** | PostgreSQL | رابطه‌ای + JSONB برای متادیتای انعطاف‌پذیر |
| **جستجوی برداری** | pgvector (افزونه Postgres) | بدون دو سیستم جدا؛ embedding + متادیتا یکجا |
| **صف وظایف / زمان‌بندی** | Celery + Redis (یا APScheduler برای ساده‌سازی فاز ۱) | کالکتورها باید زمان‌بندی‌شده و مستقل اجرا شوند |
| **لایه LLM** | LiteLLM (پروکسی یکپارچه) | سوییچ آزاد بین APIهای ابری و Ollama محلی (تصمیم کاربر: هر دو) |
| **جستجوی وب آنلاین** | SearXNG (self-host، رایگان) یا Tavily/Brave API | برای پرسش آنلاین و Deep Research — قابل تعویض از تنظیمات |
| **رونویسی صوت** | faster-whisper (محلی) یا API | تبدیل آپلود صوتی به متن |
| **OCR عکس** | Tesseract (محلی) یا VLM | تبدیل عکس به متن قابل جستجو |
| **استخراج فایل** | pypdf, python-docx, python-pptx | PDF/Word/PowerPoint |
| **Embedding** | sentence-transformers (محلی) یا API | برای فاز ۱ محلی و رایگان |
| **RSS/HTTP** | feedparser + httpx | استاندارد |
| **فرانت‌اند** | Next.js (React) + TailwindCSS — **فارسی/RTL** | تعاملی و مدرن برای داشبورد |

```
  GET  /api/v1/items            → فهرست آیتم‌ها (فیلتر: دسته، منبع، امتیاز، زمان، camp=US/CN/EU)
  GET  /api/v1/rivalry          → نمای تقابل چین-آمریکا (دو ستون + تایم‌لاین + شاخص‌ها)
  GET  /api/v1/trends           → ترندهای داغ
  GET  /api/v1/bulletins        → بولتن‌ها
  POST /api/v1/sources          → افزودن منبع جدید (فاز ۲)
  POST /api/v1/alerts/config    → تنظیم هشدار
  POST /api/v1/watch            → افزودن موضوع/شخص به پایش

[پژوهش]
  POST /api/v1/research         → شروع کار پژوهشی (deep research)
  GET  /api/v1/research/{id}    → وضعیت + گام‌ها (شفافیت)
  POST /api/v1/ask              → پرسش-وپاسخ RAG (حافظه داخلی)
  POST /api/v1/ask-online       → پرسش-وپاسخ آنلاین Perplexity-style (وب زنده + ارجاعات)
  POST /api/v1/files            → آپلود فایل/عکس/صوت
  GET  /api/v1/files/{id}       → وضعیت پردازش فایل (استخراج/رونویسی)
  POST /api/v1/summarize        → خلاصه‌سازی لینک/PDF

[کتابخانه]
  GET/POST /api/v1/library      → مدیریت کتابخانه شخصی
```

### ۸.۲ زیر-مرحله‌های پیاده‌سازی بک‌اند (هر کدام با تأیید شما)

| زیر-مرحله | محتوا | خروجی قابل آزمایش |
|---|---|---|
| **۲-الف** | اسکلت پروژه + دیتابیس + مهاجرت‌ها + Docker Compose بالا | `docker compose up` سالم؛ جداول ساخته شوند |
| **۲-ب** | کالکتور arXiv + RSS + پایپ‌لاین (AI Gate، Dedup، Classify، Score) | اجرای دستی: آیتم‌های واقعی در دیتابیس |
| **۲-ج** | API REST (items, trends, filters) + RAG (ask) + لایه LiteLLM | `GET /api/v1/items` جواب بدهد؛ سؤال فارسی → پاسخ با ارجاع |
| **۲-د** | حلقه Deep Research + بولتن + هشدار داشبوردی | گزارش پژوهشی نمونه تولید شود |
| **۲-هـ** | تست، مستندسازی، پاکسازی نهایی | پوشش تست؛ سند راهنمای اجرا |

### ۸.۳ نکات فنی مهم

- **pgvector:** جستجوی برداری داخل همان Postgres — بدون سرویس اضافه.
- **LiteLLM:** یک interface واحد؛ مدل و provider از `.env` عوض می‌شود (Ollama اضافه/کم شود بدون تغییر کد).
- **AI Gate ارزان:** اول فیلتر کلیدواژه (رایگان)، فقط موارد مبهم به LLM سبک می‌روند — کنترل هزینه.
- **زمان‌بندی:** فاز ۱ با APScheduler داخل worker (ساده‌تر)؛ مهاجرت به Celery+Redis در فاز ۲ اگر حجم بالا رفت.
